# USWDS Audit: cozy_cafe

## 1. Patience bars and time badges use color as the sole state indicator
**Problem:** Customer patience is displayed as a small colored bar (green when full, depleting toward empty) alongside a tiny percentage badge ("60%", "0%"). The bar relies entirely on color (green-to-empty) to communicate urgency — no pattern, shape change, icon, or secondary encoding. The "Patience: Lo" label on Oliver's row is truncated and nearly invisible. A user with red-green color insensitivity (~4.5% of the population per NIH) cannot distinguish patience levels. Additionally, the time badges ("2m", "5m") use small text on colored backgrounds with questionable contrast ratios — the green badge with dark text appears below the 4.5:1 AA threshold.
**Guideline:** USWDS Design Principle 1.3 (Embrace Accessibility); PART 2 Section 2.1 (Color Independence, Normal Text Contrast); PART 3 Section 3.2 (Magic Number 50+)
**Fix:** Add a secondary encoding beyond color: use a fill pattern, numeric percentage displayed prominently, or an icon (warning triangle when patience is low). Enlarge badge text to minimum 16px (`sm` token). Ensure text-on-badge contrast meets magic number 50+ (grade difference of 50 between text and background). Display the "Patience" label in full — never truncate critical status information.

## 2. Star rating and "Customers Served" subtitle are illegibly small
**Problem:** The rating display in the header ("Rating: [stars] 4/5" and "Customers Served: 25") is rendered at an extremely small size — well below the USWDS-recommended 16px minimum for readable body text, and likely below even the `3xs` token (13px). Individual stars are indistinguishable at this scale. The "Customers Served: 25" subtitle appears to be around 8-10px, failing the USWDS minimum text size guideline and making it effectively invisible to users with any vision impairment. This undermines trust — key performance feedback is unreadable.
**Guideline:** USWDS Design Principle 1.2 (Earn Trust — "Be reliable, consistent, and honest"); PART 2 Section 2.2 (Minimum Text Size: 16px); PART 4 Section 4.1 (Type Scale — `3xs` = 13px is the absolute floor)
**Fix:** Increase the star rating area substantially. Render stars at a minimum of 24px (spacing token `3` = 24px) so individual stars are clearly distinguishable. Increase the subtitle text to at least `sm` (16px). Consider moving the rating to a more prominent position if it's important user feedback.

## 3. Inconsistent panel header colors break visual continuity
**Problem:** "Today's Specials" has a dark brown header background while "Customers" has a sage green header. These are sibling panels at the same hierarchy level but use completely different hues, suggesting different importance or function. USWDS emphasizes consistency through its "Promote Continuity" principle and its color token system — same-level elements should use the same color family. The current approach uses what appears to be 3+ unrelated color families (brown, green, pink, tan) without a clear semantic mapping, violating the 60/30/10 proportion guidance.
**Guideline:** USWDS Design Principle 1.4 (Promote Continuity — "provide a consistent experience"); PART 3 Section 3.1 (Theme Consistency, 60/30/10 Proportion); PART 8 Section 8.1 (Visual Hierarchy)
**Fix:** Choose a single primary color family for same-level panel headers. Use the USWDS approach: one primary color for panel headers (~60%), a secondary color for accents and interactive elements (~30%), and accent colors sparingly (~10%). If the brown/green distinction is semantically meaningful (e.g., "your menu" vs "customer queue"), document that mapping and ensure it's communicated through more than just color.

## 4. Bottom icon buttons (Inventory/Research/Crafting) rely on ambiguous icons with tiny labels
**Problem:** The three bottom-right buttons use abstract icons (a bag, a flask/beaker, and a wrench-like shape) with very small text labels underneath. The notification badges (red circles with numbers) are small and may fail the 3:1 UI component contrast requirement against the button backgrounds. Per USWDS plain language and accessibility guidelines, icon-only or icon-primary controls are a significant barrier — icons are culturally dependent and often ambiguous. The labels appear to be below `3xs` (13px), the smallest USWDS type token.
**Guideline:** USWDS PART 6 Section 6.1 (Icon + Label — "Icons alone are often ambiguous"); PART 7 Section 7.1 (Plain Language, Action-Oriented labels); PART 2 Section 2.2 (Minimum Text Size); PART 8 Section 8.2 (Icon + Text)
**Fix:** Increase icon size to at least 24×24px and labels to at least `xs` (15px). Make labels always visible (not only on hover). Increase notification badge size and ensure badges have 3:1 contrast against their background. Consider using more universally recognizable icons or adding descriptive tooltips.

## 5. Music slider lacks sufficient handle-to-track contrast and has no visible value indicator on the control itself
**Problem:** The music slider shows "Music: 70%" as text, but the slider track and handle use similar muted green tones with insufficient contrast between them. The handle does not stand out clearly from the track, making it hard to locate the current position at a glance. Per USWDS accessibility guidelines, UI components must have at least 3:1 contrast against adjacent colors. The slider also lacks tick marks or any secondary position indicator — a user relying on the visual slider alone (without reading the "70%" text) would struggle to determine the approximate value. This is a form control without a directly associated visible label per USWDS form guidelines.
**Guideline:** USWDS PART 2 Section 2.1 (UI Component Contrast — 3:1 minimum); PART 2 Section 2.4 (Visible Labels); PART 6 Section 6.2 (Helper Text); PART 8 Section 8.3 (States and Interactivity — hover/active states)
**Fix:** Increase the contrast between slider handle and track — use a distinctly different color or a visible border on the handle (e.g., `base-dark` handle on `primary-lighter` track). Add tick marks at 0%, 25%, 50%, 75%, 100% for quick reference. Ensure the label "Music" is visually associated with the slider control as a proper form label.
