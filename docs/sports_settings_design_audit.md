# Design Audit: Sports Settings

**Screen:** In-game Video/Graphics Settings panel  
**Source:** Game UI toolkit showcase  
**Audited Against:** Apple Human Interface Guidelines (1987 Desktop Interface)  
**Date:** 2026-02-07

---

## Audit Summary: Sports Settings

### Critical Issues (Fix Immediately)

1. **Color-Only Bar Indicators With No Text or Pattern Alternative (Color §3.1, Accessibility §8.1)**: Every setting row includes a horizontal colored bar (green fill on a dark track) intended to communicate the setting's current value or impact level. However, these bars convey information through color alone — there are no numeric scales, percentage labels, tick marks, or pattern fills to provide a redundant encoding. A colorblind user, a user on a poorly calibrated display, or anyone viewing a monochrome output cannot interpret what these bars mean. Worse, the bars' purpose is itself ambiguous: for "Graphics quality: Ultra" the bar seems to indicate quality level, but for "Motion blur: 7" or "Gamma: 1.9" the bar's meaning is unclear — is it showing quality? Performance cost? Percentage of maximum?  
   → **Fix**: Remove decorative bars or make them meaningful by adding clear labels (e.g., "Low ← → High"), numeric tick marks, or percentage indicators. Ensure bar meaning is supplemented by shape, position, or text — never color alone.

2. **Pervasive Technical Jargon Without Explanation (Plain Language §7.1)**: The settings list is saturated with graphics-engineering vocabulary that typical players will not understand: "V Sync," "Anti-Aliasing method," "TSR (Temporal Super Resolution)," "Dynamic resolution," "Framerate target," "Gamma," and "Screen percentage." The HIG explicitly requires user vocabulary, not programmer vocabulary. "TSR (Temporal Super Resolution)" is particularly egregious — it's a multi-word technical phrase with an acronym that even many PC gamers wouldn't recognize, and the parenthetical "explanation" is just more jargon.  
   → **Fix**: Replace or supplement technical terms with plain-language equivalents: "V Sync" → "Sync to Display," "Anti-Aliasing method" → "Edge Smoothing," "TSR" → "Smart Upscaling," "Dynamic resolution" → "Auto-Adjust Quality," "Gamma" → "Brightness Curve," "Framerate target" → "Target Frame Rate," "Screen percentage" → "Render Scale." Add brief plain-language descriptions in the help panel for each setting.

3. **Help Panel Text Is Completely Generic and Uninformative (See-and-Point §1.3, Feedback §1.7)**: The right-side help panel for the selected "Window mode" setting reads: "Adjust this setting to customize your gaming experience." This sentence is a content-free tautology — it could be pasted onto literally any setting in any application and would be equally meaningless. It tells the user nothing about what Window mode is, why they'd change it, or how the options differ. The "Current: Borderless window" line duplicates the value already visible on the left side. The help panel exists to solve the jargon problem but utterly fails to do so.  
   → **Fix**: Write genuinely informative descriptions for every setting. For Window mode: "Controls how the game appears on your screen. Fullscreen gives the best performance, Borderless Window lets you switch to other apps quickly, and Windowed runs the game in a resizable window." Each description should explain what the setting does and what trade-offs the options represent.

4. **No Save/Apply Confirmation for Potentially Destructive Settings (User Control §1.6, Feedback §1.7, Forgiveness §1.8)**: There is no visible "Apply," "Save," or "Confirm" button anywhere on the screen. Video settings like Resolution and Window mode can render the display unreadable if an incompatible option is selected. Without an explicit apply-and-confirm mechanism (the standard pattern: "Keep these settings? Reverting in 15 seconds…"), users risk being unable to see or interact with the screen to revert their change.  
   → **Fix**: Add an "Apply" button that triggers a confirmation dialog with a countdown revert timer for display-altering settings. At minimum, provide clear feedback about whether changes are applied immediately or on confirmation.

### Major Issues (Fix Soon)

5. **Inconsistent Control Affordances Across Settings (Consistency §1.4)**: Some settings display visible `<` and `>` arrow controls flanking the value text (Window mode, Resolution, V Sync, Dynamic resolution, Graphics quality, Texture quality), indicating they are discrete selectors that cycle through predefined options. Other settings show no arrows at all (Screen percentage, Max FPS, Gamma, Motion blur, Framerate target), suggesting a different interaction model — perhaps a continuous slider. Yet all settings are presented in the same visual list with no explanation of why controls differ. Users cannot predict how a setting will behave before interacting with it, violating the expectation that the same visual pattern produces the same interaction.  
   → **Fix**: Use visually distinct control styles for discrete selectors versus continuous sliders. Discrete options should show clear arrow buttons; continuous sliders should show a draggable track with min/max labels. Don't mix two interaction models in identical visual containers.

6. **Two Bar Styles Mixed Without Explanation (Consistency §1.4, Aesthetic Integrity §1.10)**: Settings with `<` `>` arrows display segmented/stepped bars (distinct colored blocks with gaps between them), while settings without arrows display continuous solid-fill bars. These two completely different bar visualizations are interspersed throughout the same list with no legend, label, or explanation of why they differ. The segmented bars seem to represent discrete quality tiers while the solid bars represent continuous ranges, but this distinction is implicit and easily missed. The visual inconsistency creates noise and confusion.  
   → **Fix**: Use a single bar style, or if two styles are necessary, visually separate them into different groups and provide a clear legend explaining what each style represents. Ensure the distinction is communicated through more than subtle shape differences.

7. **Flat Visual Hierarchy — All Settings Have Equal Weight (Aesthetic Integrity §1.10, See-and-Point §1.3)**: The 13 settings are presented in a single undifferentiated vertical list with no grouping, no section dividers, and no visual separation between logically distinct categories. Display settings (Window mode, Resolution), performance settings (V Sync, Max FPS, Framerate target, Dynamic resolution), quality settings (Graphics quality, Texture quality, Anti-Aliasing method), and adjustment settings (Gamma, Screen percentage, Motion blur) are all intermixed. The sole section header "Graphics" sits above the entire list but provides no sub-categorization. Users scanning for a specific setting must read every label sequentially.  
   → **Fix**: Group settings under labeled sub-headers ("Display," "Performance," "Quality," "Effects") with spacing or subtle dividers between groups. This enables faster scanning, creates a meaningful hierarchy, and helps users understand which settings are related.

8. **Low-Contrast, Undersized Arrow Controls (Accessibility §8.1, §8.3, See-and-Point §1.3)**: The `<` and `>` symbols used to cycle through discrete setting values are small gray text characters with minimal contrast against the dark charcoal background. On the non-selected rows, these arrows are particularly faint — they nearly vanish into the background. They lack any button shape, border, or background that would signal interactivity, making them look like decorative punctuation rather than controls. The HIG requires that small objects use high-contrast colors and that interactive elements be visually recognizable.  
   → **Fix**: Increase arrow size and contrast significantly. Use solid arrow icons (▶ ◀) rather than text characters. Add a subtle button background, border, or padding to create a visible tap/click target. Ensure arrows are clearly visible on both selected and unselected rows.

9. **No Indication of Value Ranges, Limits, or Position (WYSIWYG §1.5, Feedback §1.7)**: When navigating setting values with `<` `>`, users have no indication of how many options exist, where the current value falls within the available range, or whether they've reached the minimum or maximum. For "Graphics quality: Ultra," is Ultra the highest option? For "Framerate target: 66 FPS," what's the range — 30 to 240? Users must blindly cycle through values to discover the full set of options. The bars provide some visual hint, but their meaning is too ambiguous to serve this purpose reliably.  
   → **Fix**: Dim or hide the arrow on the side where no more options exist. Show a position indicator (e.g., "3 of 5" or dots). Alternatively, display the full set of options with the current one highlighted, so users can see all choices at once.

10. **Selected Row Focus State Is Subtle (Color §3.1, Accessibility §8.1)**: The currently focused "Window mode" row is indicated by a thin green vertical accent bar on the left edge and a faint dashed rectangular outline around the label text. While the green accent bar is a good directional cue, the overall focus state is modest — the row background doesn't change, and the dashed outline is thin and low-contrast. On a living-room TV viewed from a couch (the typical game settings context), this subtle focus indicator may be difficult to perceive.  
    → **Fix**: Add a more prominent background highlight to the focused row — a noticeably different shade or a semi-transparent overlay. Increase the accent bar width. Ensure the focus state is distinguishable even at 10-foot viewing distances on a TV, which is the primary context for game settings.

### Minor Issues (Consider Fixing)

11. **Tab Bar Selected State Lacks Visual Prominence (Perceived Stability §1.9, Aesthetic Integrity §1.10)**: The selected "VIDEO" tab is distinguished from inactive tabs (GAMEPLAY, AUDIO, CONTROLS) by bold text and an underline. However, the difference is relatively subtle — there's no background color change, no tab shape, and no strong visual container. At a glance, it can take a moment to identify which tab is active, especially since the underline is thin. The LB/RB bumper indicators are boxed but the tabs themselves are not.  
    → **Fix**: Add a background highlight, a bottom border accent, or a filled tab shape to the selected tab. Make the active state immediately obvious through a combination of weight, color, and shape — not just a thin underline.

12. **LB/RB Labels Assume Xbox Controller Familiarity (See-and-Point §1.3, Metaphors §1.1)**: The rectangular "LB" and "RB" labels at the edges of the tab bar assume the user is holding an Xbox controller and knows that LB/RB are the left and right bumper buttons. PlayStation users (L1/R1), Switch users (L/R), and keyboard/mouse users have no obvious mapping. These abbreviations require memorization of a specific controller layout.  
    → **Fix**: Use recognizable controller button icons that match the connected input device rather than text abbreviations. Dynamically swap icons based on the detected controller type (Xbox, PlayStation, Switch, keyboard). If text must be used, consider showing the full label ("Left Bumper / Right Bumper").

13. **Right Panel Wastes Large Screen Area (Aesthetic Integrity §1.10)**: The description panel on the right occupies approximately 40% of the screen width but contains only a title, one short sentence, and a "Current:" value — three lines of text in a vast empty space. The area below the description text is completely blank dark space, creating a visually unbalanced layout where the dense left side contrasts sharply with the sparse right side.  
    → **Fix**: Expand the help panel's content: add visual previews comparing quality levels, performance impact indicators ("Low / Medium / High CPU usage"), recommended values for common hardware, or a graphic illustrating what the setting affects. If richer content isn't available, reduce the panel's width allocation and rebalance the layout.

14. **"Anti-Aliasing method" Row Has Noticeably Different Typography (Consistency §1.4)**: The "Anti-Aliasing method" label appears to be rendered in a smaller font size than other setting labels, likely because the text string is longer. Its value, "TSR (Temporal Super Resolution)," is also visually smaller and more compressed than values in other rows. This one row breaks the consistent typographic rhythm of the entire settings list, making it look like a different kind of element.  
    → **Fix**: Use a consistent font size for all setting labels regardless of text length. If a label or value is too long, truncate with an ellipsis and show the full text in the help panel, or abbreviate the label ("AA Method") rather than shrinking the font.

15. **No Scroll Position Indicator for a Long List (Perceived Stability §1.9, Feedback §1.7)**: The settings list shows 13 items visible on screen. There is no scroll bar, scroll track, position indicator, or "more below" affordance to tell users whether additional settings exist beyond the visible area. Users cannot determine if they've seen all available settings or if more are hidden below the fold.  
    → **Fix**: Add a subtle scroll position indicator on the right edge of the settings list — a thin scroll track showing relative position, or a "Page 1 of 2" indicator. If all settings are visible, no indicator is needed, but the user should be confident that's the case.

16. **Bottom Action Buttons Are Small and Peripheral (See-and-Point §1.3)**: The "Y — Reset to default" and "B — Back" controller actions in the bottom-right corner are the only non-navigation actions available on this screen, yet they are presented in small text tucked into the corner. The colored circles (yellow Y, red B) are tiny and easy to overlook, especially when the user's visual attention is drawn to the dense settings list on the left side of the screen.  
    → **Fix**: Increase the size and prominence of the action buttons. Consider placing them in a dedicated action bar that spans the bottom of the screen, giving them consistent positioning and adequate visual weight. Use larger button icons with clear labels.

17. **"Reset to default" Scope Is Ambiguous (Forgiveness §1.8, Plain Language §7.1)**: The "Y — Reset to default" action doesn't specify its scope. Does pressing Y reset only the currently focused setting (Window mode) to its default? All settings in the Graphics section? All Video settings? All settings across all tabs? Users who want to reset a single setting can't be sure they won't accidentally reset everything, creating fear of using the feature — the opposite of forgiveness.  
    → **Fix**: Clarify the scope in the label: "Reset This Setting," "Reset All Video Settings," or "Reset All Settings." If the action resets multiple settings, show a confirmation dialog listing what will be changed before proceeding.

### Strengths

- **Dark, Game-Appropriate Color Theme**: The deep charcoal/navy background with light text is well-suited for an in-game settings overlay. The muted palette avoids visual competition with gameplay and creates a focused environment for configuration.
- **Green Accent Color for Selection**: The green left accent bar on the selected row provides a clear directional cue and is visually consistent with the green used in the bar indicators, establishing a cohesive accent color throughout the screen.
- **Tabbed Navigation Structure**: The top tab bar (GAMEPLAY, VIDEO, AUDIO, CONTROLS) follows a standard, logical categorization familiar to gamers. Users can quickly navigate between settings categories without leaving the settings screen.
- **Contextual Help Panel Concept**: The right-side panel providing a description of the currently selected setting is a thoughtful UX pattern. Even though the current descriptions need significant improvement, the infrastructure for contextual help is in place and can be enhanced.
- **Consistent Row Layout Pattern**: All settings follow a recognizable row structure: label on the left, value in the center, and a visual bar on the right. This predictable layout lets users quickly scan and compare settings.
- **Back Action Clearly Available**: The "B — Back" button in the bottom-right corner provides a visible escape route from the settings screen, ensuring users always know how to exit.

---

### Overall Score: 4/10

The Sports Settings screen establishes a functional foundation with its tabbed navigation, consistent row layout, and contextual help panel concept, but is undermined by pervasive usability issues across nearly every HIG category. The most damaging problems are the completely uninformative help text (which renders the right panel decorative rather than functional), the heavy reliance on unexplained technical jargon, and the color-only bar indicators that are both ambiguous in meaning and inaccessible to colorblind users. The inconsistent control affordances — where some settings show discrete selector arrows and others don't, with two different bar visualization styles mixed together without explanation — violate the consistency principle and force users to experiment to discover each setting's interaction model. The absence of a save/apply confirmation mechanism for potentially display-breaking settings like Resolution and Window mode is a notable safety gap. The subtle focus state, tiny arrow controls, and ambiguous "Reset to default" scope further erode confidence in the interface. To reach an acceptable standard, the screen needs genuinely informative help descriptions, plain-language setting names, consistent control styles, prominent focus indicators sized for TV viewing distances, and a safe apply/revert mechanism for display settings.
