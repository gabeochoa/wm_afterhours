# Design Audit: Empire Tycoon Screen

*Audited against the Apple Human Interface Guidelines (1987 Desktop Interface)*
*Date: February 7, 2026*

---

## Audit Summary: Empire Tycoon Dashboard

### Critical Issues (Fix Immediately)

1. **[Title Text Near-Zero Contrast — HIG 3.2, 8.1]**: The "DREAM INCORPORATED" title uses a light cyan/ice-blue outlined stroke font on a light blue gradient background. The contrast ratio between the title text and its background is extremely low — the text nearly disappears into the surrounding sky-blue chrome. HIG 3.2 explicitly requires that "text and thin lines have sufficient contrast to be easily visible," and HIG 8.1 requires high-contrast availability for vision accessibility. The game's brand name is the single most important identifying element on screen, yet it is the hardest text to read.
   → **Fix**: Either darken the title text significantly (deep navy, dark teal, or white with a drop shadow), or place the title on a contrasting banner/background strip. At minimum, target a 4.5:1 contrast ratio. If the outlined/stroke style is desired, add a solid fill or a dark outer glow so the letterforms remain legible against the gradient.

2. **[Color-Only Differentiation for Trending Indicators — HIG 3.1, 8.1]**: The "^" caret symbol is used as a "Trending Up" indicator next to production rates and project items, but the caret is rendered in the same muted text color as surrounding content with no shape, icon, or pattern distinction. The legend "^ = Trending Up" is placed far away in a separate card on the right edge. HIG 3.1 states "color coding is redundant with shape/position/pattern" and requires the design to "work in black and white first." A user unfamiliar with the convention (or a colorblind user) has no way to parse the meaning of a lone caret character without finding the distant legend.
   → **Fix**: Replace the "^" text character with a small upward-arrow icon (▲) rendered in green or another semantically meaningful color. Include both the icon and the color so the indicator is redundantly coded. Move the legend closer to the data, or eliminate the need for a legend entirely by using a universally understood arrow icon.

3. **[Inconsistent Action Button Styling — HIG 1.4, 2.7]**: The three primary action buttons ("Speed Up", "Prioritize", "New Project") at the bottom center exhibit three different visual treatments. "Speed Up" and "Prioritize" use a golden-yellow fill with a darker yellow/orange dashed border and rounded-pill shape, while "New Project" uses a similar fill but with a distinctly different border style (solid line, slightly different corner radius, and different proportions). All three are peers in the action hierarchy, yet they do not look like siblings. HIG 1.4 requires "visual styles consistent throughout" and warns against "custom implementations of standard controls."
   → **Fix**: Unify all three buttons to share identical border style, border radius, padding, and fill color. If one button is meant to be a primary action and the others secondary, express that hierarchy through a single controlled variable (e.g., fill vs. outline) while keeping all other properties identical.

4. **[Flat Visual Hierarchy in Data Cards — HIG 1.10]**: The Production Overview and Current Projects cards present all data items at the same font size, weight, and color. Production labels ("Toys:", "Snacks:", "Gadgets:") and their values ("5200/min", "3800/min", "3100/min") are visually indistinguishable in weight. Similarly, project names and their completion percentages share identical styling. HIG 1.10 requires "clear visual hierarchy — most important elements stand out" and warns against "flat visual hierarchy — everything same prominence." Users must read every item linearly rather than scanning for important values.
   → **Fix**: Differentiate labels from values — make values bolder or larger, and labels lighter or smaller. Consider making the highest production rate or most-complete project visually prominent (e.g., larger font size, accent color, or bold weight) so users can spot key data at a glance.

5. **[No Default or Primary Action Indicated — HIG 2.7]**: Three action buttons sit side by side with identical visual weight. None is marked as a default or primary action. HIG 2.7 requires that a "default button [is] doubly outlined" to indicate the primary action a user would most likely take. In a tycoon/management game, one action (likely "New Project" or "Speed Up") should be visually promoted as the most common next step.
   → **Fix**: Designate one button as the primary action using a heavier fill, bolder border, larger size, or a double-outline treatment. Demote the other two to a secondary visual style (lighter fill, outline-only, or smaller size) so the visual hierarchy guides the user toward the most common action.

### Major Issues (Fix Soon)

6. **[Sidebar Navigation Disconnected from Content — HIG 1.10, 1.9]**: The left sidebar (Rides, Food, Upgrades, Finance) floats against the left edge with no visual container or background differentiation connecting it to the main content area. The sidebar icons are small (~48px), placed on cream/beige pill-shaped backgrounds, and separated from the main dashboard by a large expanse of empty blue space. This creates a spatial disconnect — users may not immediately recognize these as the primary navigation for switching dashboard views. HIG 1.9 (Perceived Stability) requires "familiar landmarks" and HIG 1.10 requires that "graphics support understanding."
   → **Fix**: Add a subtle vertical container or background panel behind the sidebar to group the navigation buttons visually. Increase the icon/button size for better touch/click targets. Consider adding an active-state indicator (highlighted background, border, or left-edge accent) to show which section is currently displayed.

7. **[Notification Badge Lacks Affordance — HIG 1.7, 3.1]**: The "Upgrades" button has a small red dot (notification badge) at its top-right corner, but the dot contains no count, label, or further context. HIG 1.7 requires that feedback be "brief, direct, uses user vocabulary." A red dot communicates "something" but not "what" or "how many." The dot is also very small relative to the icon, making it easy to overlook.
   → **Fix**: Either enlarge the badge and add a count (e.g., "3") so users know the scope of pending upgrades, or add a subtle animation (pulse, glow) to draw attention. If the badge represents a one-time notification rather than a count, use a different visual treatment (e.g., a "NEW" label) to convey the nature of the alert.

8. **[Chat Log Area Has Poor Contrast and Spatial Separation — HIG 3.2, 1.10]**: The bottom-left chat/log area ("GlobalChat: New area unlocked! Explore now." and "DevTeam: Update v2.0 is live – check patch notes!") uses small dark text on a semi-transparent muted background strip. The text contrast is borderline, and the area is not clearly delineated from the action buttons or the milestone progress bar adjacent to it. The chat area, action buttons, and milestone bar all compete for the same bottom strip of screen real estate with no clear spatial boundaries.
   → **Fix**: Give the chat area a distinct, opaque background container with visible borders. Increase text size or weight for readability. Add clear vertical or horizontal dividers between the chat log, the action buttons, and the milestone progress bar to establish three distinct zones.

9. **[Milestone Progress Bar Lacks Context — HIG 1.7, 7.1]**: The "Next Milestone" progress bar shows "65%" but provides no information about what the milestone is, what reward it unlocks, or what actions advance it. HIG 1.7 requires that feedback "uses user vocabulary" and provides "clear explanation." HIG 7.1 requires messages to be "concise and simple" but also informative. A bare percentage without context does not help users make decisions.
   → **Fix**: Add a brief label describing the milestone (e.g., "Next Milestone: Theme Park Tier 3") either above or within the progress bar. Consider adding a tooltip or expandable detail showing what actions contribute to milestone progress and what reward awaits.

10. **[Inconsistent Card Sizing and Alignment — HIG 1.4]**: The Production Overview card and the Current Projects card appear to have different widths despite being presented as a side-by-side pair. The Production Overview card is narrower and the Current Projects card stretches wider. Their top edges are roughly aligned, but the bottom edges are ragged because they contain different amounts of content. HIG 1.4 requires that "visual styles consistent throughout" — paired content containers should share dimensions for visual balance.
    → **Fix**: Set both cards to equal widths within their shared row. If content length differs, let the shorter card have whitespace at the bottom rather than shrinking it. Align both top and bottom edges, or use a consistent minimum height so the cards feel structurally paired.

11. **[Excessive Typography Variety — HIG 1.4, 1.10]**: The screen uses at least four distinct type treatments: (a) an outlined/stroke display font for "DREAM INCORPORATED," (b) a serif-like font for card headers ("Production Overview," "Current Projects"), (c) a different weight or family for data values ("5200/min"), and (d) a stylized/hand-drawn font for the action buttons ("Speed Up," "Prioritize," "New Project"). HIG 1.4 (Consistency) requires a unified visual language. Four competing typeface styles fragment the visual identity and make the screen feel like a collage of unrelated elements.
    → **Fix**: Reduce to two typefaces maximum — one display/title font and one body/UI font. Apply the display font to the game title only. Use the body font for all card headers, data labels, values, button labels, and navigation labels. Vary weight and size within that single body font to create hierarchy instead of introducing new typefaces.

12. **[Bottom Navigation Icons Visually Disconnected — HIG 1.4, 1.9]**: The bottom-right icons (Shop, Settings, Leaderboard) use circular golden/yellow icon buttons that are visually distinct from every other element on the screen. They share neither the cream/beige styling of the sidebar buttons, the white styling of the content cards, nor the golden-yellow styling of the action buttons. They also sit against the darker bottom strip, further isolating them. HIG 1.4 warns against inconsistent visual treatment for controls of the same category.
    → **Fix**: Harmonize the bottom navigation with the sidebar navigation — use the same container shape, background color, and icon style. If the bottom nav must remain separate, at minimum match the border-radius and background color of the sidebar buttons to create a sense of family membership.

### Minor Issues (Consider Fixing)

13. **[Typos in Project Names — HIG 7.1]**: "New Rollercoasser" should be "New Rollercoaster" and "Robot Masoot" should be "Robot Mascot." While technically a content issue rather than a visual design issue, HIG 7.1 requires that messages be clear and professional. Misspellings erode user confidence in the interface and suggest a lack of polish. In a showcase context, they undermine the credibility of the entire design system.
    → **Fix**: Correct both spellings. Establish a spell-check pass as part of the design review process for all user-visible strings.

14. **[Happiness Indicator Placement and Scale — HIG 1.10, 1.9]**: The Happiness indicator (smiley face + green bar + "85%") is placed in the upper right below the currency display but visually isolated from the game state it relates to. The green progress bar is very small, making it hard to read at a glance. HIG 1.10 requires clear visual hierarchy and HIG 1.9 requires stable, logical placement. A key game metric should be more prominently placed and sized.
    → **Fix**: Either enlarge the happiness indicator and give it a proper card/container matching the Production Overview cards, or integrate it into the main content area. Group all key metrics (currency, happiness, milestone) into a unified status bar at the top for consistent spatial organization.

15. **[Currency Icons Below Dollar Amount Are Ambiguous — HIG 1.3, 3.1]**: Below the "$1,250,980" display, two small icons appear (they look like an hourglass/jar and a pie chart or coin). Their meaning is unclear — they could represent different currencies, resource types, or account features. HIG 1.3 (See-and-Point) requires that users can discover meaning by looking, not guessing. The icons are small, unlabeled, and lack tooltips or text.
    → **Fix**: Add text labels below or beside each icon (e.g., "Gold," "Gems" or "Income," "Expenses"). Increase icon size so the visual detail is readable. If they represent secondary currencies, show their values next to them.

16. **[Background Gradient Creates Ambiguous Zones — HIG 1.10, 1.9]**: The screen background transitions from a light blue at the top, to a medium sky blue in the middle, to a purple/mauve strip at the bottom. This creates an impression of three visual zones, but the zone boundaries don't align with functional boundaries. The action buttons sit on the blue zone, the chat log and milestone bar sit on the mauve zone, and the sidebar spans both. The gradient implies structure that doesn't match the actual layout.
    → **Fix**: Either make the background a single uniform color (letting cards and containers define the structure), or align the gradient transitions with actual UI zones (header, content, footer). If a multi-zone background is desired, use hard breaks with subtle color shifts rather than a smooth gradient that suggests arbitrary banding.

17. **[Legend Card ("^ = Trending Up") Orphaned from Data — HIG 1.10]**: The legend explaining "^ = Trending Up" is placed in its own small card on the far right edge of the screen, separated from both the Production Overview and Current Projects cards that contain the actual "^" indicators. Users must scan right, read the legend, then scan back left to apply that knowledge to the data. HIG 1.10 requires that "graphics support understanding, not just decoration."
    → **Fix**: Embed the legend directly within or immediately adjacent to the card headers (e.g., as a subtitle: "^ indicates trending up"). Alternatively, replace the "^" with a self-explanatory icon so no legend is needed at all.

18. **[Inconsistent Spacing Between Sidebar Buttons — HIG 1.4]**: The four sidebar navigation buttons (Rides, Food, Upgrades, Finance) appear to have slightly uneven vertical spacing between them. The gap between Rides and Food looks tighter than the gap between Upgrades and Finance. HIG 1.4 requires visual consistency in layout spacing.
    → **Fix**: Set a uniform vertical gap (e.g., 8px or 12px) between all sidebar buttons. Verify pixel-level alignment to ensure visually equal spacing throughout the navigation stack.

### Strengths

- **Clear real-world metaphor**: The tycoon/business management metaphor is immediately understandable — production rates, projects, milestones, and currency all map to familiar business concepts (HIG 1.1 — Metaphors).
- **Color palette is cohesive in tone**: Despite specific contrast issues, the overall palette (sky blue, cream, golden yellow, white) creates a warm, inviting, casual-game atmosphere. The colors feel intentional and themed rather than random.
- **Action buttons are discoverable**: The three primary actions (Speed Up, Prioritize, New Project) are prominently placed and clearly labeled with verb phrases, making them easy to find and understand (HIG 1.3 — See-and-Point).
- **Progress indicators present**: Both the project completion percentages and the milestone progress bar provide quantitative feedback about game state (HIG 1.7 — Feedback and Dialog).
- **Sidebar navigation provides clear categories**: The four navigation categories (Rides, Food, Upgrades, Finance) use both icons and text labels, supporting recognition over recall (HIG 1.3).
- **Chat log provides contextual updates**: The GlobalChat and DevTeam messages at the bottom give users real-time information about game events without blocking interaction (HIG 1.7).

### Overall Score: 4/10

The Empire Tycoon dashboard demonstrates a solid conceptual foundation — the business/tycoon metaphor is clear, actions are labeled with verbs, and key game state is surfaced. However, the execution suffers from numerous consistency and contrast failures. The near-invisible title text, inconsistent button styling, flat data hierarchy, and fragmented typography undermine usability at every level. The spatial organization scatters related elements (sidebar disconnected from content, legend orphaned from data, metrics spread across all four edges) instead of grouping them logically. Most critically, the lack of contrast on the primary title and the reliance on a lone "^" character for trend indicators would fail basic accessibility requirements. Addressing the five critical issues — title contrast, trend indicator coding, button consistency, data hierarchy, and primary action indication — would significantly improve both aesthetics and usability.
