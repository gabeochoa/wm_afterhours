# Design Audit: 9-Slice Borders Screen

*Audited against the Apple Human Interface Guidelines (1987 Desktop Interface)*
*Date: February 7, 2026*

---

## Audit Summary: 9-Slice Borders Showcase

### Critical Issues (Fix Immediately)

1. **[Color as Sole Differentiator for Tinted Panels — HIG 3.1, 8.1]**: The "Double-Width & Tinting" row presents Gold Tint, Blue Tint, Red Tint, and Green Tint panels that are distinguished from each other *only* by their fill color. There is no variation in border style, pattern, icon, label styling, or shape. A colorblind user or a monochrome display would see four identical rectangles with identical labels differing only in the word "Gold/Blue/Red/Green." HIG 3.1 requires that "color coding is redundant with shape/position/pattern" and that designs "work in black and white first."
   → **Fix**: Add a secondary visual cue to each tinted panel — a unique border pattern, a small swatch icon, diagonal hatching, or a distinct border weight — so that each tint is identifiable without relying on hue perception. At minimum, vary the border style per tint (e.g., solid, dashed, dotted, double) so the panels are distinguishable on a monochrome display.

2. **[Inconsistent Text Sizing Creates Chaotic Hierarchy — HIG 1.10, 1.4]**: Text label sizes within the "Panel Styles" row vary dramatically and unpredictably. "Simple" and "Ornate" are rendered in a medium font, "Double Line" is noticeably smaller, "Thick" jumps to a much larger bold weight, "Decorative" returns to medium, and "Heavy" is the largest of all. Since these panels are peers demonstrating different *border* styles, their text labels should be identical in size to avoid suggesting that text size is related to the border variant. HIG 1.10 warns against designs where "different things look the same" and conversely where visually identical things are treated differently, and HIG 1.4 requires visual styles to be consistent throughout.
   → **Fix**: Standardize the label font size across all panels in a given row. If the text must scale to fill available space, add a fixed-size subtitle below each panel (or above, in the section header area) so the identifying label is consistent regardless of panel dimensions.

3. **[Section Headers Nearly Invisible — HIG 1.10, 3.2]**: Section headers ("Panel Styles (filled background)," "Border Only (transparent center)," etc.) use a small, gold/tan italic serif font rendered directly on the dark brown background. The combination of small size, low-contrast color (gold on dark brown), italic styling, and lack of any visual container or separator makes these headers extremely easy to miss. They function as critical navigational landmarks for understanding the showcase, yet they are the least visually prominent elements on screen. HIG 1.10 requires "clear visual hierarchy — most important elements stand out" and HIG 3.2 requires "text and thin lines have sufficient contrast to be easily visible."
   → **Fix**: Increase the section header font size significantly (at least 1.5× current). Use white or a light cream color for better contrast against the dark background. Consider adding a horizontal rule, increased top margin, or a subtle background highlight to separate sections and make the headers unmissable.

4. **[Trans A / Trans B Labels Have Dangerously Low Contrast — HIG 3.2, 8.1]**: The "Trans A" and "Trans B" panels in the "Border Only" row use a gold/tan text color on a transparent background that reveals the dark brown page behind it. The resulting contrast ratio between gold text and dark brown background is poor — the labels are significantly harder to read than the white-on-cream or dark-on-cream labels of neighboring panels. HIG 3.2 explicitly states that "text and thin lines have sufficient contrast to be easily visible."
   → **Fix**: Use white text for labels on transparent-background panels, or add a semi-opaque dark text shadow / backdrop behind the label text to ensure readability regardless of what shows through the transparency. Alternatively, use a lighter text color with higher contrast against the dark page background.

5. **[Flat Visual Hierarchy — Sections Have Equal Visual Weight — HIG 1.10]**: All five sections (Panel Styles, Border Only, Different Sizes, Double-Width & Tinting, Interactive Elements) sit at the same visual level with no meaningful differentiation in spacing, prominence, or container treatment. The page reads as a continuous flat grid of boxes rather than a structured, navigable showcase. The title "9-SLICE BORDERS" at the top is the only element with distinct treatment, and even it is understated. HIG 1.10 warns against "flat visual hierarchy — everything same prominence."
   → **Fix**: Add significantly more vertical spacing between sections (at least 2× the current inter-row gap). Give each section a subtle container or distinct background region. Make section headers large enough to serve as visual anchors. Consider adding numbering or progressive indentation to guide the reader through the showcase logically.

### Major Issues (Fix Soon)

6. **[Inconsistent Spacing Between Panels — HIG 1.4]**: Horizontal gaps between panels vary both within and across rows. In the "Panel Styles" row, the gap between "Simple" and "Ornate" appears wider than the gap between "Double Line" and "Thick." The "Different Sizes" row places "Wide Panel" and "Tall" with a large empty gap between "Large Panel" and "Wide Panel" on the left side. The "Double-Width & Tinting" row has tighter spacing on the left (Double Width, Double Ornate) and wider spacing between the tinted panels. HIG 1.4 requires consistent visual treatment throughout.
   → **Fix**: Use a single, consistent horizontal spacing token between all panels in every row. If panels have different widths, let the spacing remain constant and allow the row to expand or wrap naturally. Avoid ad-hoc gaps that break the visual rhythm.

7. **[Mixed Typography Styles Undermine Consistency — HIG 1.4, 7.1]**: The screen uses at least three distinct typographic treatments: (1) the title "9-SLICE BORDERS" in uppercase monospace, (2) section headers in italic serif with gold coloring, and (3) panel labels in a proportional or pixel-style font at varying sizes. These three styles have no clear hierarchy or relationship to each other. HIG 1.4 requires terminology and visual styles to be consistent throughout, and HIG 7.1 calls for concise, simple, understandable text.
   → **Fix**: Establish a clear typographic hierarchy — e.g., one typeface family with bold for titles, regular weight for section headers, and a consistent size for panel labels. If the retro/game aesthetic demands a pixel font, use it consistently with clear size differentiation (large for titles, medium for section headers, standard for labels).

8. **["Heavy" Border Panel Dominates Row Disproportionately — HIG 1.10]**: In the "Panel Styles" row, the "Heavy" panel is significantly larger than its peers — both its border thickness and overall dimensions exceed the other panels by a wide margin. While this may be demonstrating that the heavy border style requires more visual space, the result is that "Heavy" visually dominates the row and draws the eye away from the other five styles. This creates the impression that "Heavy" is more important or is the default, which is misleading. HIG 1.10 requires that "graphics support understanding, not just decoration."
   → **Fix**: Normalize panel sizes within the row so all six border styles have roughly equal visual weight. If the heavy border inherently requires more space, increase the other panels slightly to reduce the size disparity, or add a note explaining that the larger size is a consequence of the border thickness.

9. **["Tall" Panel Isolated Far from Row Context — HIG 1.10, 1.9]**: The "Tall" panel in the "Different Sizes" row is pushed to the far right edge of the screen, visually disconnected from the other size variants (Small, Medium, Large Panel, Wide Panel) on the left. There is a large horizontal gap between "Wide Panel" and "Tall," making it unclear whether "Tall" belongs to this section or is a separate element. HIG 1.9 (Perceived Stability) requires familiar landmarks and consistent grouping so elements don't feel randomly placed.
   → **Fix**: Position "Tall" closer to the other size variants, or place it on a second row beneath the others. If horizontal space is limited, consider wrapping the row rather than stretching it across the full screen width with an orphaned element.

10. **[No Interactive Feedback Demonstrated for "Click Me!" — HIG 1.7, 5.1]**: The "Interactive Elements" section includes a gold "Click Me!" button, but the showcase does not demonstrate any hover, pressed, focused, or active state for this button. HIG 1.7 requires "immediate feedback confirms every action" and HIG 5.1 requires "visual feedback shows what's selected." A showcase that labels something "interactive" but only shows a static state is incomplete.
    → **Fix**: Add visual demonstrations of the button's interactive states — show the hover state (lighter gold or border glow), pressed state (darkened or inset), and focused state (visible focus ring). Consider adding a small state label below each to explain the demonstrated state.

11. **[Nested Panels Section Lacks Explanatory Context — HIG 1.3, 7.1]**: The "Nested Panels" area shows two small panels labeled "Inner" and "Panel" inside a larger container, but there is no explanation of what nesting demonstrates or why a user would want nested 9-slice borders. The label "Nested Panels" alone is insufficient — users scanning the showcase won't understand the purpose or use case. HIG 1.3 (See-and-Point) requires that users can discover meaning by looking, and HIG 7.1 requires messages to be informative and user-oriented.
    → **Fix**: Add a brief description (e.g., "Panels can be nested inside each other while maintaining crisp borders at every level") below or beside the nested panel demo. This transforms the element from a cryptic visual into an informative showcase item.

### Minor Issues (Consider Fixing)

12. **[Dialog Text Inside Panel Is Barely Readable — HIG 3.2]**: The text "This is a dialog using 9-slice. Corners stay crisp!" inside the dialog panel in the "Interactive Elements" row uses a small font size on a beige/cream background. While the contrast between dark text and cream background is adequate, the font size is noticeably smaller than other labels on the screen, making it harder to read — especially given the amount of text in this panel compared to single-word labels elsewhere.
    → **Fix**: Increase the font size of the dialog body text to match the base label size used elsewhere in the showcase, or reduce the text content to a shorter phrase that can be rendered larger. Ensure multi-word content remains legible at the chosen size.

13. **[Section Header Overlap / Crowding with Content — HIG 1.10]**: Several section headers sit extremely close to the top edges of their first panel row, with minimal vertical spacing between the header text and the panels below. The "Interactive Elements" header appears to nearly touch the panels from the "Double-Width & Tinting" row above it. This tight vertical stacking makes it difficult to tell which section a header belongs to and creates visual clutter.
    → **Fix**: Add generous top padding above each section header (at least equal to the height of one panel row) to create clear visual separation between sections. The header should feel like it "owns" the content below it, not like it's squeezed between two rows.

14. **[Title "9-SLICE BORDERS" Underemphasized — HIG 1.10]**: The page title sits in a bordered panel at the top of the screen, using the same border styling as the content panels below it. While the text is centered and uses a distinct uppercase monospace treatment, the border panel wrapping it makes it look like just another showcase element rather than a page heading. The title competes with the content panels for attention rather than clearly establishing itself as the page label.
    → **Fix**: Remove the border panel around the title or give it a significantly different visual treatment (e.g., wider, spanning full width with no side borders, larger font size, or a different background color) so it reads unambiguously as a page-level heading.

15. **[No Indication of Which Borders Are Best for Which Use Cases — HIG 1.3]**: The showcase presents 20+ border variants without any guidance on when to use each one. A developer or designer viewing this showcase has no information about which border style is appropriate for dialogs, which for buttons, which for menus, etc. HIG 1.3 (See-and-Point) requires that users can discover and understand available options by looking.
    → **Fix**: Add brief usage annotations — e.g., "Simple: General-purpose panels," "Ornate: Title screens and headers," "Thick: Important dialogs." This transforms the showcase from a visual catalog into a usable reference guide.

16. **[Double Width / Double Ornate Labels Are Tiny and Hard to Read — HIG 3.2]**: The "Double Width" and "Double Ornate" panels in the "Double-Width & Tinting" row have very small label text relative to their panel size. The labels are rendered at what appears to be the smallest text size on the entire screen, making them difficult to read against their cream/beige backgrounds. This is especially problematic because these are the only panels where the label is noticeably smaller than the panel's visual footprint would accommodate.
    → **Fix**: Scale up the label text for these panels to match the label size used in similarly-sized panels elsewhere (e.g., the "Simple" or "Ornate" panels in the first row). Labels should maintain a consistent visual weight regardless of their panel's border style.

17. **[Background Color Monotony — HIG 1.10]**: The entire page uses a single, uniform dark brown background with no variation. While this provides a clean canvas for the panels, it also makes the page feel static and heavy. There is no visual texture, gradient, or subtle variation to create depth or guide the eye through the content. Combined with the flat hierarchy of sections, the uniform background contributes to a monotonous visual experience.
    → **Fix**: Consider adding subtle background variation between sections — a very slight lightening or darkening of the background in alternating sections — to help the eye distinguish regions. Alternatively, add a subtle noise texture or vignette to give the background visual interest without distracting from the content.

18. **[Monospace Title Font Reduces Readability — HIG 7.1]**: The title "9-SLICE BORDERS" uses a monospace uppercase typeface that, while thematically consistent with a retro/game toolkit, reduces readability compared to a proportional font. The uniform character widths and uppercase treatment make the title harder to scan quickly. For a page-level heading that users should recognize instantly, readability should take priority over stylistic consistency.
    → **Fix**: If the monospace font is a deliberate design system choice, consider increasing the title font size or adding letter-spacing to improve readability. Alternatively, use a proportional display font for top-level headings while reserving the monospace font for labels and code-related content.

### Strengths

- **Comprehensive Border Catalog**: The showcase demonstrates a wide variety of 9-slice border styles — simple, ornate, double line, thick, decorative, heavy, transparent, tinted, and nested — providing thorough coverage of the toolkit's capabilities.
- **Clear Functional Grouping**: Panels are logically organized into meaningful categories (filled background, border-only, size variants, tinting, interactive), making it straightforward to locate specific border types.
- **Effective Size Demonstration**: The "Different Sizes" section clearly shows that 9-slice borders maintain their corner fidelity at various dimensions (small through wide and tall), which is the core selling point of the 9-slice technique. The "Wide Panel — Good for menus" annotation is a helpful contextual note.
- **Tinted Panel Variety**: The tinting section demonstrates that borders can be colorized, which is a valuable capability for game UIs that need themed panels for different contexts (e.g., gold for rewards, red for warnings).
- **Nested Panel Demonstration**: Showing that panels can be nested without visual degradation is an important technical showcase that developers need to see. The inclusion of this example anticipates a real-world use case.
- **Interactive Element Inclusion**: The "Click Me!" button and dialog panel demonstrate that 9-slice borders work for interactive components, not just static containers — this extends the showcase beyond decoration into functional UI territory.

### Overall Score: 4/10

The 9-Slice Borders showcase succeeds as a comprehensive visual catalog — it covers an impressive range of border styles, sizes, and use cases in a single screen. The logical grouping into sections is sound, and the inclusion of interactive and nested examples shows thoughtful coverage. However, the presentation suffers from significant hierarchy, contrast, and consistency issues that undermine its effectiveness as a reference. Section headers are nearly invisible, text sizes vary wildly within peer groups, the "Trans A/B" labels have poor contrast, and color-tinted panels rely entirely on hue for differentiation. The typography mixes three distinct styles without clear rationale, and spacing is inconsistent both within and across rows. For a toolkit showcase that developers will reference when building their own UIs, these presentation issues risk propagating poor patterns. Strengthening the visual hierarchy, standardizing text sizing, improving contrast, and adding usage guidance would transform this from a raw catalog into a polished, instructional design reference.
