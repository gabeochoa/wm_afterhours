# Microsoft Win95 Guidelines Audit: All Screens (2026-02-15)

## 1. Text Truncation and Clipping Across Multiple Screens
**Severity:** Critical
**Affected screens:** cards, cozy_cafe, empire_tycoon, fighter_menu, horizontal_drag, modals, stepper_showcase, text_overflow, text, kirby_options, parcel_corps_settings
**Problem:** Text is visibly clipped or truncated without ellipsis across numerous screens. In `cards`, the "Semi-Transparent" card description reads "This panel uses opacity to create a translo..." cut off at the edge. In `cozy_cafe`, customer patience text ("Patience: Lo...") overlaps with the percentage indicator. In `fighter_menu`, the sub-tab labels ("System Opti", "Game Optio", "Display Opt", "Sound & La", "Network Op", "Button Settings") are all truncated to illegibility. In `modals`, button labels on the right ("Simple M...", "Info Dia...", "Op...", "Backgroun...", "Confirm:...") are all cut off at the viewport edge. In `stepper_showcase`, the card selector shows "HealerWarriorMage" as a single run-on string and the Warrior card description is clipped ("high de..."). In `text`, the body text reads "Body text for readable content that flows naturally and r..." cut off mid-word. In `parcel_corps_settings`, the quest text is clipped at the right edge.
**Guideline:** Internationalization -- The Win95 guidelines require text to have expansion room. Controls must be sized to accommodate their content, and text should never be clipped without an explicit ellipsis or tooltip fallback.
**Fix:** Implement automatic ellipsis truncation with tooltip on hover for all text controls. Ensure containers are sized to fit their text content, or use scrolling/wrapping. For tab labels, use abbreviations with full text tooltips rather than hard clipping.

## 2. Absence of Standard Title Bars With System Menu and Min/Max/Close Buttons
**Severity:** Critical
**Affected screens:** Nearly all screens including absolute_positioning, animation_basic, animation_declarative, animation_interactive, animation_looping, animation_spring, auto_text_color, bevel_borders, button_variants, buttons, checkboxes, circular_progress, colors, drag_drop, flex_alignment, forms, hstack_showcase, meters_gauges, navigation_bar_demo, pagination, radio_buttons, self_align, separators, setting_row_showcase, tab_container, tabbing, text, text_input, text_overflow, text_shadow, text_stroke, themes, toasts, toggle_switches, vstack_showcase
**Problem:** The vast majority of screens have no window chrome whatsoever -- no title bar, no system menu icon, no minimize/maximize/close buttons. The Win95 guidelines mandate that every primary and secondary window must have a standard title bar with a system menu box (double-click to close), a title, and minimize/maximize/close buttons. Only the `aim_chat` screen implements anything resembling a proper title bar. Screens like `angry_birds_settings` and `casual_settings` have close buttons but they are non-standard circular red "X" icons positioned inside the content area rather than in a proper title bar.
**Guideline:** Windows -- Chapter 6: "Every window should have a title bar that includes the system menu icon, title text, and Minimize, Maximize, and Close buttons."
**Fix:** Add standard Win95-style title bars to all primary and secondary windows. The title bar should include a 16x16 system menu icon at far left, the window title in the center-left, and Minimize/Maximize/Close caption buttons at far right using the standard glyphs.

## 3. Non-Standard Button Appearance (Rounded Corners, Flat Styling, Missing 3D Borders)
**Severity:** Major
**Affected screens:** buttons, button_variants, simple_button, tabbing, casual_settings, angry_birds_settings, mini_motorways_settings, language_demo, toasts, navigation_bar_demo, kart_select, race_results, cozy_cafe, empire_tycoon, potion_crafting, shop_interface
**Problem:** Buttons throughout the toolkit use rounded corners, pill shapes, flat fills, and gradient styles instead of the standard Win95 3D raised border appearance. In `simple_button`, the main "Click Me!" button is a large coral-colored rounded rectangle with no 3D effect. In `button_variants`, all "Filled" buttons are flat colored rectangles with rounded corners. The `tabbing` screen uses four large brightly colored buttons (magenta, cyan, lime green, orange) with no 3D borders. The Win95 standard button has a light highlight on top-left edges and a dark shadow on bottom-right edges to create a raised 3D appearance. The `bevel_borders` screen demonstrates this capability exists in the toolkit but it is not applied to actual buttons.
**Guideline:** Controls -- Standard push buttons must use the system 3D border appearance: light top/left edges, dark bottom/right edges, creating a raised look that becomes sunken when pressed.
**Fix:** Default button styles should use the Win95 3D bevel borders (the toolkit already has `bevel_borders` support). Remove rounded corners from standard buttons; use sharp rectangular borders. Reserve rounded/pill shapes only for explicitly non-standard custom controls.

## 4. Missing Standard Menu Bars
**Severity:** Major
**Affected screens:** All settings screens (angry_birds_settings, casual_settings, deadspace_settings, flight_options, islands_trains_settings, kirby_options, mini_motorways_settings, parcel_corps_settings, powerwash_settings, sports_settings), all game screens (cozy_cafe, empire_tycoon, kart_select, neon_strike, potion_crafting, race_results, shop_interface, rubber_bandits_menu, fighter_menu)
**Problem:** No screen in the entire toolkit implements a standard Win95 menu bar (File, Edit, View, Help). The only screen that comes close is `aim_chat` which shows "File Edit Insert People" -- but even this lacks the standard underline/accelerator key convention. The `hstack_showcase` shows a "File Edit View Settings" toolbar pattern, but it is styled as a demonstration rather than a functional menu bar. The Win95 guidelines state that every primary window should have a menu bar providing access to all application commands.
**Guideline:** Menus -- Chapter 7: "The menu bar provides access to most commands in an application. It appears below the title bar and contains menu titles."
**Fix:** Add a standard menu bar below the title bar on all primary windows. At minimum include File and Help menus. Use standard accelerator key underlines (e.g., "_F_ile", "_E_dit"). Implement keyboard access via Alt+letter.

## 5. Toggle Switches Used Where Checkboxes Are Required
**Severity:** Major
**Affected screens:** angry_birds_settings, casual_settings, mini_motorways_settings, toggle_switches, setting_row_showcase, forms, parcel_corps_settings, islands_trains_settings
**Problem:** Mobile-style toggle switches (iOS-like pill toggles) are used extensively for binary on/off settings instead of standard Win95 checkboxes. In `angry_birds_settings`, Music, Sound, and Vibrate all use green toggle switches. In `casual_settings`, the same pattern appears. In `mini_motorways_settings`, Night Mode, Vibration, Hold to Draw/Delete, and Colorblind Mode all use toggle switches. In `toggle_switches`, the entire Settings panel uses toggle switches for Notifications, Sound Effects, and Vibration. The toggle switch is not a standard Win95 control. The correct control for binary options is the checkbox (square box with checkmark).
**Guideline:** Controls -- Chapter 8: "A check box is a control that allows the user to select or clear an option... Use check boxes for settings that are binary (on or off)."
**Fix:** Replace all toggle switches with standard Win95 checkboxes for binary on/off settings. Checkboxes should be square with a checkmark when selected, positioned to the left of the label text.

## 6. Non-Standard Use of Color for Differentiation Without Redundant Cues
**Severity:** Major
**Affected screens:** checkboxes, button_variants, buttons, tabbing, toasts, horizontal_drag, race_results, kart_select, forms, neon_strike, potion_crafting
**Problem:** Color is used as the sole differentiator for control states and categories without providing redundant visual cues. In `checkboxes`, the "Primary" checkbox row is dark blue, "Secondary" is purple, and "Accent" is red -- the only way to distinguish them is color. In `tabbing`, Option A through D are magenta, cyan, lime green, and orange with no other distinguishing feature. In `toasts`, Info/Success/Warning/Error buttons rely on teal/green/pink/red color coding. In `horizontal_drag`, priority tags (Security patch, Data loss fix, etc.) are differentiated only by color. The Win95 guidelines and accessibility standards require that color must never be the only means of conveying information, as this fails for colorblind users and high-contrast modes.
**Guideline:** Accessibility -- "Never use color as the only means of conveying information. Always provide a redundant cue, such as a text label, shape, or pattern."
**Fix:** Add text labels, icons, shape variation, or border patterns as redundant cues alongside color. For example, toast types should have distinct icons (i for info, checkmark for success, triangle for warning, circle-X for error) in addition to their color coding.

## 7. Missing OK/Cancel Button Pairs in Dialog-Style Windows
**Severity:** Major
**Affected screens:** potion_crafting, shop_interface, drag_drop, horizontal_drag, animation_basic, animation_declarative, animation_interactive, animation_looping, animation_spring, cozy_cafe, empire_tycoon, neon_strike, race_results, kart_select, rubber_bandits_menu, tabbing
**Problem:** Many screens that function as dialogs or secondary windows lack the standard OK/Cancel button pair at the bottom right. The Win95 guidelines require that every dialog box have OK and Cancel buttons, and that property sheets additionally have an Apply button. Some settings screens do include OK/Cancel/Apply (e.g., `angry_birds_settings`, `casual_settings`, `flight_options`, `mini_motorways_settings`, `powerwash_settings`), but many game and utility screens lack commit/cancel semantics entirely. The `potion_crafting` screen has a "Brew!" button but no way to cancel. The `shop_interface` has "Purchase" but no "Cancel" to dismiss the dialog.
**Guideline:** Windows -- "Every dialog box should provide at least a command button for the user to close the window... Include OK and Cancel."
**Fix:** Add standard OK and Cancel buttons at the bottom-right of all dialog-style windows. For property sheets, add Apply as well. Ensure Cancel always reverts changes and closes the window. Ensure Escape maps to Cancel.

## 8. Stepper/Spinner Controls Used Instead of Standard Drop-Down List Boxes
**Severity:** Major
**Affected screens:** stepper_showcase, islands_trains_settings, powerwash_settings, sports_settings, setting_row_showcase, flight_options, parcel_corps_settings, navigation_bar_demo, mini_motorways_settings
**Problem:** The toolkit uses left/right arrow "stepper" controls (< Value >) extensively for selecting from a set of predefined options (e.g., Resolution: < 2560x1440 >, Quality: < Medium >, Language: < English >). This control pattern requires repeated clicking to cycle through options and provides no visibility into available choices. In `stepper_showcase`, Resolution, Quality, Language, Difficulty, and Framerate all use this pattern. In `islands_trains_settings`, Mode and Resolution use < > steppers. In `sports_settings`, nearly every setting uses this pattern. The Win95 standard control for selecting from a predefined list is the drop-down list box (combo box), which shows all options at once when opened.
**Guideline:** Controls -- Chapter 8: "Use a drop-down list box when you want to provide a fixed set of choices... The list drops down when the user clicks the arrow."
**Fix:** Replace stepper/spinner controls with standard drop-down list boxes (combo boxes) for selecting from predefined option lists. This gives users immediate visibility into all available choices and requires only a single click to select.

## 9. Inconsistent Focus Indicator Styles
**Severity:** Major
**Affected screens:** buttons, button_variants, absolute_positioning, checkboxes, animation_basic, animation_declarative, animation_interactive, flight_options, forms, kart_select, pagination, potion_crafting, radio_buttons, scroll_view, setting_row_showcase, shop_interface, simple_button, tab_container, tabbing, text_input, toasts, toggle_switches
**Problem:** Focus indicators vary wildly across the toolkit. Some controls show a dashed white rectangle (e.g., `buttons` Normal button), some show a solid colored border (e.g., `tabbing` Option A has a yellow border), some show a glow effect, and some show no focus indicator at all. In `button_variants`, the focused "Normal" filled button has a thin white dashed border, while in `simple_button`, the focused "Click Me!" button has a dark solid border that looks like a drop shadow. In `checkboxes`, the focused "Primary" row has a thin white outline. In `text_input`, the focused Username field has a white solid border. The Win95 guidelines specify a single standard: a dotted rectangle (focus rectangle) drawn inside the control.
**Guideline:** Keyboard Interface -- "The focus is indicated by a dotted rectangle drawn within the control... The focus rectangle should be consistent across all controls."
**Fix:** Standardize all focus indicators to use a single consistent style: a 1px dotted black (or white on dark backgrounds) rectangle drawn inside the control boundary. Remove glow effects, solid borders, and colored outlines used as focus indicators.

## 10. Circular and Non-Rectangular Progress Indicators Without Standard Progress Bar
**Severity:** Minor
**Affected screens:** circular_progress, meters_gauges, cozy_cafe, forms, empire_tycoon
**Problem:** The toolkit provides circular/ring progress indicators (`circular_progress` shows four variants at 75%, 35%, 42%, 88%) and arc-style gauges (`meters_gauges` shows 25%, 50%, 90% circular gauges) that have no equivalent in the Win95 standard control set. The standard Win95 progress indicator is a horizontal rectangular bar that fills left-to-right. While the toolkit does include linear progress bars (seen in `meters_gauges` as HP/MP/XP bars and in `forms` as "Audio Level: 75%"), the circular variants are non-standard. In `cozy_cafe`, the customer "Patience" indicators appear as small inline percentage pills that do not follow standard patterns.
**Guideline:** Controls -- The standard progress indicator is a horizontal bar control. Non-standard control shapes increase the learning curve.
**Fix:** Provide standard horizontal progress bars as the default progress indicator. If circular indicators are desired for game UIs, they should be clearly documented as custom controls and should not replace the standard progress bar in toolkit demonstrations.

## 11. Slider Track and Thumb Do Not Follow Standard Trackbar Appearance
**Severity:** Minor
**Affected screens:** forms, setting_row_showcase, cozy_cafe, meters_gauges, parcel_corps_settings
**Problem:** Sliders (trackbar controls) in the toolkit do not follow the Win95 standard appearance. In `forms`, the Volume/Brightness/Difficulty sliders use a dark track with a purple fill and no visible thumb/tick marks. In `setting_row_showcase`, the Master Volume and Music Volume sliders have a thin gray track with a small green square thumb. In `cozy_cafe`, the Music slider has a rounded green track with a circular thumb. The Win95 standard trackbar has a channel (sunken groove), a slider thumb (raised 3D pointer), and optional tick marks along the track. The current implementations resemble mobile-style range inputs rather than Win95 trackbars.
**Guideline:** Controls -- "A trackbar is a control with a slider that the user can move... The control includes a channel (groove) and a slider (thumb)." The thumb should have a 3D appearance and the channel should appear sunken.
**Fix:** Style slider controls with a sunken 3D channel, a raised 3D thumb pointer, and optional tick marks. The thumb should resemble a small raised rectangular handle, not a circle or flat square.

## 12. Tab Controls With Inconsistent Tab Styles and Non-Standard Placement
**Severity:** Minor
**Affected screens:** angry_birds_settings, deadspace_settings, fighter_menu, flight_options, mini_motorways_settings, potion_crafting, powerwash_settings, shop_interface, sports_settings, tab_container, themes
**Problem:** Tab controls vary significantly in visual style across the toolkit. In `angry_birds_settings`, tabs (Audio, General, Info) appear as text labels with horizontal line separators beneath them rather than as proper tab shapes. In `deadspace_settings`, tabs are styled as a horizontal text row (Controls, Gameplay, Display and Graphic, Audio...) with the active tab highlighted in teal -- no tab shape at all. In `fighter_menu`, tabs appear as small white-bordered rectangles in a row. In `mini_motorways_settings`, tabs are rendered as plain text of varying sizes (Game, Video, Audio, Language, Controls, Cross-Save, Credits) with no tab shape. In `sports_settings`, tabs at the bottom (GENERAL, GAMEPLAY, VIDEO, AUDIO, CONTROLS) use different font sizes for active vs inactive. The Win95 standard tab control has a specific visual appearance: tabs look like folder tabs with a raised 3D border, connected to the tab page below.
**Guideline:** Controls -- "Property sheets use tabs... Each tab looks like a file folder tab, with a raised border."
**Fix:** Standardize tab controls to use the Win95 folder-tab visual style: raised 3D border on each tab, the active tab visually connected to the page below (no border between active tab and content), inactive tabs slightly recessed. Position tabs at the top of the property sheet by default.

## 13. Radio Buttons Rendered as Filled Circles Instead of Standard Open/Filled Style
**Severity:** Minor
**Affected screens:** radio_buttons
**Problem:** In the `radio_buttons` screen, radio buttons are rendered as small dark circles with a solid red fill when selected (e.g., Orange, Small, Blue selections). The unselected radio buttons appear as small dark rounded rectangles or capsules rather than open circles. The Win95 standard radio button is a small open circle when unselected and a circle with a centered solid dot when selected. The current rendering makes it difficult to distinguish radio buttons from other control types. Additionally, the group boxes around "Favorite Fruit", "Size", and "Color" use pink/magenta borders instead of the standard etched gray border.
**Guideline:** Controls -- "An option button [radio button] appears as a small circle... When the option is selected, a solid dot appears inside the circle."
**Fix:** Render radio buttons as standard open circles (approximately 12px diameter) with a centered 6px solid dot when selected. Remove the solid fill from unselected state. Use standard gray etched borders for group boxes.

## 14. Excessive Use of Rounded Corners on Panels and Containers
**Severity:** Minor
**Affected screens:** absolute_positioning, animation_basic, animation_interactive, animation_looping, animation_spring, auto_text_color, button_variants, circular_progress, decorative_frame, flex_alignment, language_demo, layout, meters_gauges, navigation_bar_demo, pagination, self_align, setting_row_showcase, simple_button, toggle_switches
**Problem:** Nearly every container, panel, and card in the toolkit uses large rounded corners (approximately 8-16px border radius). The Win95 visual style uses sharp rectangular corners for all standard window frames, group boxes, panels, and dialog boxes. Rounded corners were not part of the Windows 95 visual vocabulary and create a modern/mobile aesthetic that conflicts with the platform standard. The `absolute_positioning` screen shows this clearly: every section panel has prominent rounded corners. The `animation_basic` and related screens wrap their entire content in a single large rounded-corner panel. The `simple_button` screen places everything in a card with large rounded corners.
**Guideline:** Visual Design -- Windows 95 uses rectangular forms with sharp corners. Rounded corners are not part of the standard visual language for windows, dialog boxes, group boxes, or panels.
**Fix:** Use sharp rectangular corners (0px border radius) for all standard windows, dialog boxes, group boxes, and panels. If rounded corners are desired for specific game UI themes, make them opt-in rather than the default.

## 15. No Standard Status Bar at Bottom of Primary Windows
**Severity:** Minor
**Affected screens:** Nearly all primary window screens. Partial implementations exist in: aim_chat ("Direct Connection Established"), cozy_cafe (Music slider and chat area), empire_tycoon (Next Milestone and navigation icons), neon_strike (health/ammo HUD), race_results (controller hints)
**Problem:** The Win95 guidelines specify that primary windows should include a status bar at the bottom displaying contextual information such as the current state, selection details, or progress. Most screens in the toolkit lack any status bar. The few screens that do display bottom-bar information use non-standard styling. The `aim_chat` screen has "Direct Connection Established" in a status area, but it lacks the standard sunken 3D border panes. The `race_results` and `kart_select` screens show controller button hints (A: Select, B: Back) at the very bottom, but these are plain text without the standard status bar frame. The `language_demo` screen has "Active: ENGLISH | Font: Gaegu-Bold" at the bottom but again without standard styling.
**Guideline:** Toolbars/Status Bars -- "A status bar is an area at the bottom of a primary window that displays information about the current state of what is being viewed... Use a sunken border style."
**Fix:** Add a standard status bar at the bottom of all primary windows. The status bar should use a sunken 3D border with separate panes for different information categories (e.g., status text, selection info, keyboard state indicators). Style it using system colors (COLOR_BTNFACE background, sunken 3D borders for panes).
