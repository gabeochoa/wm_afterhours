# Design Audit: Shop Interface Screen

*Audited against the Apple Human Interface Guidelines (1987 Desktop Interface)*
*Date: February 7, 2026*

---

## Audit Summary: General Store

### Critical Issues (Fix Immediately)

1. **[Color as Sole Differentiator for Item Icons — HIG 3.1, 8.1]**: Each item in the inventory list is identified by a colored square with an abstract symbol inside (teal "+" for Health Potion, purple "-" for Mana Potion, brown "#" for Leather Armor, orange "*" for Fire Scroll, yellow "!" for Torch, orange "O" for Antidote, blue "=" for Steel Shield, gray "/" for Iron Sword). The symbols inside these squares have no semantic relationship to the items they represent — "/" does not suggest a sword, "#" does not suggest armor, and "=" does not suggest a shield. Without color, many of these icons would be indistinguishable from one another in meaning. HIG 3.1 explicitly requires that "color coding is redundant with shape/position/pattern" and the design must "work in black and white first." A colorblind user would see near-identical abstract glyphs.
   → **Fix**: Replace the abstract single-character symbols with recognizable pictographic icons — a sword silhouette for Iron Sword, a bottle for Health Potion, a shield shape for Steel Shield, etc. Each icon should be identifiable without color, using distinct shapes that map to the item's real-world metaphor (HIG 1.1).

2. **[Low-Stock Indicator Relies Solely on Color — HIG 3.1, 8.1]**: Items with low stock (Fire Scroll showing "3", Steel Shield showing "2") display their stock count in red text, while items with adequate stock show white numbers. This red-vs-white color difference is the only signal that stock is running low. HIG 3.1 requires "color not the only way to distinguish elements" and warns against "no consideration for colorblind users." A user with red-green colorblindness may not perceive any difference between the low-stock and normal-stock numbers.
   → **Fix**: Add a secondary visual indicator for low stock — a warning icon (triangle with exclamation mark), a text label ("Low!"), or a distinct background highlight behind the stock number. The red color can remain as a supplementary cue, but it must not be the only cue.

3. **[No Confirmation Step Before Purchase — HIG 1.8, 1.6]**: The "Purchase" button at the bottom of the cart panel would presumably spend 180 G of the player's 3,750 G balance with a single press. There is no indication that a confirmation dialog will appear, no ellipsis (...) on the button label (HIG 2.3 requires ellipsis when a dialog will appear), and no undo mechanism is implied. HIG 1.8 (Forgiveness) requires "users warned before irreversible actions" and HIG 1.6 (User Control) requires the user to always be able to "quit, save, or cancel." Spending in-game currency is a consequential action that should not be a single unguarded button press.
   → **Fix**: Either add an ellipsis to the button ("Purchase...") and show a confirmation dialog summarizing the transaction before completing it, or add a visible "Undo Last Purchase" option after the transaction completes. At minimum, a confirmation step should list the items, total cost, and remaining gold so the user can review before committing.

4. **[Flat Visual Hierarchy Between Left and Right Panels — HIG 1.10]**: The item list (left panel), item detail card (top right), and cart summary (bottom right) all use the same dark background treatment, the same border style, and similar visual weight. The most important interactive element — the item list where the user makes selections — has no more visual prominence than the passive detail card. The cart's "Purchase" button and the detail card's "Add to Cart" button compete for attention at equal levels. HIG 1.10 requires "clear visual hierarchy — most important elements stand out" and warns against "flat visual hierarchy — everything same prominence."
   → **Fix**: Establish a clear visual hierarchy by differentiating the panels. The item list should be the dominant element with the largest allocation of screen space (it already has this) and a slightly lighter background to draw the eye. The detail card should feel subordinate, and the cart section should visually emphasize the "Purchase" action point as the terminal step in the workflow.

5. **[Currency Symbol Placement Inconsistency — HIG 1.4, 7.1]**: The player's gold balance is displayed as "G 3,750" (symbol before number) in the top-right corner, but every price in the item list and cart uses the opposite convention: "250 G", "50 G", "180 G" (number before symbol). This inconsistency violates HIG 1.4 which requires "terminology consistent — same words for same concepts." The user encounters two different formats for the same unit of measurement on a single screen, creating unnecessary cognitive friction.
   → **Fix**: Standardize the currency format throughout the screen. Choose either "G 250" or "250 G" and apply it consistently to the balance display, all item prices, cart line totals, and the cart total. The most natural format for a game context would be a consistent suffix ("250 G") since prices in the list already use that convention.

### Major Issues (Fix Soon)

6. **[Subtitle Text Extremely Low Contrast — HIG 3.2, 8.1]**: The shop greeting "Welcome, adventurer! Browse my finest wares." is rendered in small, dim text against the dark brown background. The contrast ratio between this muted tan text and the near-black background is very low, making it difficult to read even at full screen size. HIG 3.2 requires "text and thin lines have sufficient contrast to be easily visible" and warns against "low-contrast text or thin lines." While this is flavor text, it is still presented as readable content and should be legible.
   → **Fix**: Increase the contrast by brightening the text color or increasing the font size. If the text is intended to be atmospheric and secondary, make it slightly larger and use a warmer, brighter tone of gold/cream that is still subdued but clearly legible. Alternatively, if the text is purely decorative, remove it rather than presenting illegible content.

7. **[Buy/Sell Tab Active State Insufficiently Distinct — HIG 2.7, 1.9]**: The "Buy" tab is indicated as active by a dashed yellow/gold border, while the "Sell" tab has no border and slightly dimmer text. The difference between these two states is subtle — a thin dashed line is the only visual cue. HIG 1.9 (Perceived Stability) requires that "unavailable items are dimmed, not removed" and the active state should be unambiguous. Additionally, the "Sell" tab text appears in a different color (reddish/coral) than the "Buy" tab text, which introduces a color inconsistency in what should be parallel navigation elements.
   → **Fix**: Make the active tab visually dominant — use a filled background, a solid (not dashed) border, or a connected-tab treatment where the active tab visually merges with the content panel below it. The inactive tab should appear clearly clickable but visually subordinate, using consistent text color for both tabs with only the background/border treatment changing.

8. **[Bottom Button Legend Uses Hardware-Specific Labels — HIG 1.3, 7.1]**: The bottom bar displays "A: Select   B: Back   X: Add to Cart   Y: Remove" using controller button labels (A, B, X, Y). These labels assume the user is using a specific gamepad and would be meaningless to a keyboard or mouse user. HIG 1.3 (See-and-Point) warns against "hidden commands requiring memorization" and "cryptic abbreviations or codes." The single letters "A", "B", "X", "Y" are opaque to anyone unfamiliar with this controller layout.
   → **Fix**: If the interface supports multiple input methods, show context-appropriate labels (e.g., "Enter: Select" for keyboard users). If only gamepad input is supported, add small visual icons of the actual controller buttons (colored circles matching the gamepad) next to the labels so users can match the legend to their physical controller. The text-only "X: Add to Cart" format reads as cryptic to anyone who doesn't already know which button "X" is.

9. **[Cart Section Lacks Item Management Affordance — HIG 1.2, 2.7]**: The cart shows "Health Potion x3" and "Torch x2" as plain text entries with prices, but there are no visible controls to modify cart contents — no minus button, no remove icon, no quantity stepper. The bottom legend says "Y: Remove" but there is no visual indication in the cart itself that items can be selected or removed. HIG 1.2 (Direct Manipulation) requires that users can "click/drag objects rather than typing commands" and that "visual feedback accompanies every action." The cart items feel like static labels, not interactive objects.
   → **Fix**: Add visible remove buttons (e.g., an "×" icon) next to each cart item, and optionally quantity steppers (−/+) to adjust quantities. Each cart item should look interactive — a hover/selection state, a clickable affordance — so users can directly manipulate their cart contents without relying on memorized controller shortcuts.

10. **[Price Column Uses Green Text on Dark Background with Insufficient Size — HIG 3.2]**: All price values in the item list ("250 G", "50 G", "75 G", etc.) are rendered in green text. While the green-on-dark contrast ratio is acceptable, these price figures use the same font size as other table text, making them blend into the row rather than standing out as a key decision-making data point. Prices are arguably the most important column in a shop interface — they determine whether the player can afford an item — but they do not receive commensurate visual emphasis. HIG 3.2 requires that "small objects use high-contrast colors."
    → **Fix**: Give prices slightly more visual weight — a larger font size, bold weight, or brighter shade. Consider right-aligning all prices in a consistent column so the numerical values are easy to scan and compare vertically. The price should be the most prominent data point in each row after the item name.

11. **[No Scroll Indicator for Item List — HIG 2.2, 1.7]**: The item list displays seven items (Iron Sword through Steel Shield) with no scroll bar, no scroll indicator, and no visual cue suggesting additional items might exist below the visible list. HIG 2.2 requires that scroll bars "represent the entire document dimension" and show "relative position in document." If this is the complete inventory, the absence of a scroll bar is acceptable — but there is no way for the user to know whether they are seeing all available items or only a partial view.
    → **Fix**: If the list is complete, add a subtle visual termination cue (extra padding at the bottom or a faint divider) to signal that no more items exist. If the list is scrollable, add a scroll bar or a "▼ More items" indicator at the bottom of the visible list area so users know there is additional content to discover.

### Minor Issues (Consider Fixing)

12. **[Mixed Typography Between Title and Body — HIG 1.4, 1.10]**: The "General Store" heading uses a decorative serif/script typeface while all other text on the screen (item names, column headers, descriptions, buttons) uses a monospace or pixel-style sans-serif font. This creates a jarring typographic contrast between exactly two type families with no intermediate weights or sizes bridging them. HIG 1.4 requires visual styles to be "consistent throughout," and the abrupt shift from ornate script to utilitarian monospace feels like two different designers worked on the same screen.
    → **Fix**: Either adopt a single type family throughout (using size and weight variations for hierarchy), or introduce the decorative font as a thematic accent in a controlled way — e.g., "General Store" in script, section headers in a semi-decorative font, body text in a clean proportional font. The transition between the two typefaces needs intermediate typographic steps.

13. **[Item Detail Card "Add to Cart" Button Competes with "Purchase" — HIG 1.10, 2.7]**: The "Add to Cart" button (green, upper-right detail card) and the "Purchase" button (yellow/gold, bottom-right cart panel) are both prominent, brightly colored action buttons visible simultaneously on the right side of the screen. They represent sequential steps in the shopping workflow (add items, then purchase), but their equal visual prominence does not communicate this sequence. A user encountering this screen for the first time might not immediately understand which button to press first. HIG 1.10 requires that "different things look different" and visual hierarchy should guide the user through the workflow.
    → **Fix**: Establish a visual hierarchy between the two buttons. "Add to Cart" should be styled as a secondary action (e.g., outlined button, smaller size, or muted color) since it is a repeatable intermediate step. "Purchase" should be the primary action (larger, bolder, more saturated color) since it is the terminal, consequential action. This sequential visual weight guides the user from browsing to purchasing.

14. **[Column Headers Lack Visual Separation from Data Rows — HIG 1.10, 3.2]**: The column headers "Item," "Type," "Stock," and "Price" are rendered in the same font size and a slightly dimmer color than the data rows beneath them. There is no horizontal rule, background fill, or typographic distinction (such as bold or uppercase) separating the header row from the data rows. The header row and the first data row (Iron Sword) are almost indistinguishable in visual treatment, making it harder to parse the table structure at a glance.
    → **Fix**: Differentiate the header row with a distinct visual treatment — a subtle background fill, a bottom border separating headers from data, bold or uppercase text, or a slightly different font size. The headers should be immediately recognizable as labels rather than data entries.

15. **[Selected Row Highlight Style Inconsistent with Tab Selection — HIG 1.4]**: The selected item row (Health Potion) uses a warm golden/amber background highlight to indicate selection, while the active tab (Buy) uses a dashed yellow border with no fill. These are both "selected" states for different types of controls, but they use completely different visual treatments — one is a fill, the other is a border. HIG 1.4 requires that "same action produces same result throughout the application" and warns against "same action doing different things in different contexts." While tabs and list items are different controls, their selected states should share a visual language.
    → **Fix**: Establish a cohesive selection vocabulary. If filled backgrounds indicate selection, apply a filled (not outlined) treatment to the active tab as well. If bordered outlines indicate selection, use an outlined treatment on the selected list row. The visual language for "this is active/selected" should be consistent across control types, even if the specific styling details differ slightly.

16. **[No Visual Connection Between Selected Item and Detail Card — HIG 1.7, 1.10]**: When Health Potion is selected in the list (highlighted row), the detail card on the right shows its information — but there is no visual connector between the two elements. The detail card floats independently in the top-right corner with no arrow, shared color, highlight bridge, or spatial proximity cue linking it to the selected row. A user might not immediately understand that the detail card updates based on their list selection.
    → **Fix**: Add a visual connection between the selected list item and the detail card. Options include: a small arrow or pointer from the detail card pointing to the selected row, a shared background color that bridges the gap, or positioning the detail card adjacent to the selected row (if the list is short enough). At minimum, the detail card's header or border should use the same golden highlight color as the selected row to create a visual link.

17. **[Cart Total Line Lacks Visual Separation — HIG 1.10, 3.2]**: The "Total: 180 G" line in the cart section sits directly above the "Purchase" button with no visual separator (line, increased spacing, or background change) between the cart item list and the total. The total is one of the most important pieces of information on the screen — it tells the user exactly how much they are about to spend — but it blends into the cart layout without standing out. HIG 1.10 requires "most important elements stand out."
    → **Fix**: Visually separate the total from the item list with a horizontal rule or increased spacing, and make the total amount more prominent — larger font size, bold weight, or a distinct color that differentiates it from individual line item prices. Consider also showing the remaining balance after purchase (e.g., "Remaining: 3,570 G") so the user can immediately assess the impact.

18. **[Decorative Item Icon Symbols Violate See-and-Point — HIG 1.3]**: The symbols inside the item icon squares (/, +, -, #, *, !, O, =) appear to be arbitrary punctuation characters rather than meaningful identifiers. A user cannot look at the "=" icon and intuit "Steel Shield," nor can they look at "/" and think "Iron Sword." HIG 1.3 (See-and-Point) requires "recognition over recall" and warns against "cryptic abbreviations or codes." These symbols function as decoration rather than communication — they add visual noise without aiding identification.
    → **Fix**: Either replace the symbols with recognizable pictographic icons (sword, potion bottle, scroll, shield, etc.) or remove the symbols entirely and rely on colored squares with item-type indicators. If the abstract symbols are a deliberate aesthetic choice, supplement them with a small item silhouette or pictogram that actually conveys the item's identity.

### Strengths

- **Clear Shopping Metaphor**: The "General Store" interface uses a familiar retail metaphor that users immediately understand — browse items, view details, add to cart, purchase. This maps directly to real-world shopping experiences and satisfies HIG 1.1's requirement for concrete, understandable metaphors.
- **Logical Left-to-Right Workflow**: The screen layout follows a natural workflow progression: browse items (left) → view details (top right) → manage cart (bottom right). This left-to-right, top-to-bottom flow matches natural reading order and creates an intuitive interaction sequence without requiring instructions.
- **Item Detail Card Provides Context**: The right-side detail card displays the item name, type badge, description ("Restores 50 HP instantly."), and price in a clean, scannable format. This gives the user all the information they need to make a purchasing decision without leaving the shopping flow.
- **Cart Shows Running Total**: The cart section displays individual items with quantities and line totals, plus a running "Total: 180 G" — providing WYSIWYG feedback on the financial impact of the user's selections before they commit to purchasing (HIG 1.5).
- **Gold Balance Always Visible**: The player's current gold balance ("G 3,750") is persistently displayed in the top-right corner, giving the user constant awareness of their purchasing power without requiring navigation to a separate screen.
- **Welcoming Flavor Text**: The shopkeeper greeting "Welcome, adventurer! Browse my finest wares." uses warm, in-character language that establishes the game world's tone and makes the interface feel alive (HIG 7.1 — friendly without being misleading).

### Overall Score: 4.5/10

The General Store interface demonstrates solid conceptual design — the shopping metaphor is clear, the workflow layout is logical, and the cart-with-total pattern provides good transactional feedback. These structural foundations are strong. However, the execution falls short across several fundamental HIG principles. The most critical failures are accessibility-related: item icons rely on color-only differentiation with cryptic abstract symbols that communicate nothing about the items they represent, and low-stock warnings use red text as the sole indicator. The currency format inconsistency ("G 3,750" vs "250 G") is a basic polish failure. The lack of a purchase confirmation step for an irreversible currency-spending action violates forgiveness principles. The visual hierarchy is flat, with competing action buttons, undifferentiated panel treatments, and a table header row that blends into the data. Typography mixes a decorative script title with monospace body text without any bridging elements. While the screen successfully communicates "this is a shop where you buy things," it needs significant refinement in accessibility, visual hierarchy, interaction feedback, and typographic consistency to deliver a polished, usable shopping experience.
