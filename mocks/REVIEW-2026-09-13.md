## Item 14: diagonal offsets come from replaying margins twice

`UIComponent::rect()` already includes the margin. For an absolute node the mock
used `left = rect.x - parent.rect.x` while retaining CSS `margin-left`; CSS adds
that margin to the positioned border box again. The same occurs vertically.

| Historical screen and node | Captured margin on each edge | Reported diagonal offset |
|---|---:|---:|
| `decorative_frame`, `frame_inner1` | 2.4px | about 2px |
| `decorative_frame`, `frame_bg` | 8px | 8px |
| `cozy_cafe`, `frame_inner1` | 4.2px | about 4px |
| `cozy_cafe`, `frame_bg` | 14px | 14px |

The mock now subtracts the corresponding margin from absolute `left` and `top`.
This preserves CSS margins while positioning the border box at its recorded origin.
Today's decorative frame no longer has those same margined nodes, but today's
`cozy_cafe` slider handle has a 195.825px left margin, so the mock defect still matters.

`node mocks/test_mock.mjs` exercises zero, positive and negative margins with an
independent border-box-origin equation. It fails against the old implementation and
passes against the fix. It checks emitted positioning styles, not browser flex layout.

## Items 13 and 16: text-height differences are not missing messages

The mock maps `Text` to `fit-content`, then renders `.lbl` with `position:absolute`.
An absolutely positioned label contributes no intrinsic height to its parent. The
mock also supplies a fixed 10px browser font and `white-space:nowrap`; the dump does
not contain the actual font metrics needed to reproduce wrapped Raylib text.

The old multiline specimens had native heights of 54px and 72px. A zero-height CSS
text box explains the entire recorded -54px and -72px differences. Calling this only
a difference in wrapped line counts was misleading. Today's surviving
`ml_wrap_selfsizing` is 56px high. The mock still cannot independently check that
height. Copying the captured height into the CSS would hide the limitation.

Both AIM captures contain all three named message labels under one root, marked
visible. Their native heights were 18px and are now 20px. They are the three
`Percent/Text` nodes affected by the same intrinsic-height limitation. The snapshots
provide no evidence of three unreachable native widgets. They cannot prove the
absence of detached entities because the dump only traverses reachable root children
and silently skips invalid child references.

Keep text-sized discrepancies labeled as mock limitations until text configuration,
font loading, wrapping and measurement are represented. The existing `underText`
flag identifies these cases, but the sheet's headline total still counts them.
